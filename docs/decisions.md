# Decision record

Ideas that were tried or considered and not shipped, so they are not retried blindly. The design is in `docs/superpowers/specs/2026-10-08-find-that-book-design.md`.

## Tried and set aside

| Idea | State | Revisit when |
|---|---|---|
| Time budget per Open Library lookup phase (fail faster when Open Library does not answer) | Tried, not kept. The reason was not recorded. Today each attempt times out at 10 s with 2 retries. A circuit breaker now stops requests after repeated failures (see Changed after the first draft). | Searches hang on a slow Open Library. Measure the slow phase first. |
| Error shown as a balloon under the search box, and the AI notice as a "Basic search" pill with a popover | Prototyped, not kept. The toast was chosen. | The toast needs a rethink, for example when the empty page after a dismissed toast (F4 in `docs/ui-tests/README.md`) is a problem. The balloon keeps the message next to the search box. |
| Error shown as a modal dialog, and the AI notice as a header chip with a tooltip | Prototyped, not kept. A modal is heavy for an error that only needs a retry. | A message that needs a decision from the user. |

## Out of scope by choice

| Idea | Reason |
|---|---|
| LLM re-ranking | Ranking stays deterministic so the order is testable and explanations cannot contradict it. Only reconsider behind a flag. |
| Persistent cache | The one-hour in-memory cache is enough for one instance. |
| ISBN matching | Not in the brief. |
| Hosted live demo | Needs a hosting account. |
| Remote (HTTP) transport for the MCP server, with auth and rate limits | The MCP server is a local stdio process of the user's own client, so it needs none of them. A remote transport would need auth, the rate limit and the security headers the API has. Revisit when someone needs to reach it over a network. |
| A readiness tool, resources and prompts in the MCP server | One tool, `search_books`, is all the use case needs. |
| Telemetry and a Docker image for the MCP server | Telemetry is wired by the API, not by `AddFindThatBook`, and a client starts the MCP server as a local process. Revisit with a remote transport. |
| A stdio mode in `FindThatBook.Api`, or an MCP server that calls the HTTP API | A separate project on `ISearchService` keeps the API unchanged and needs no running API. |
| `dotnet run` as the MCP server command | A build step before the server starts is slow and was not checked for stray stdout output. Clients run the built dll. |
| Masking the reader's search text in telemetry | The text is the app's core input, not a credential, and it is needed to debug results. Reconsider if logs leave the operator's own collector. |
| A telemetry backend in `docker-compose.yml` | The app only exports OTLP. Point `OTEL_EXPORTER_OTLP_ENDPOINT` at an existing collector. |
| Docker image build check | Done by hand on 2026-10-10, 2026-10-13 and 2026-10-14: the image builds and serves the UI and API, and the CI publish job builds it and smoke-tests it. No automated test in the repo runs searches against the image. |
| Stop button, or an editable search box during a search | The owner kept the box locked and added no Stop (2026-10-10). One search at a time keeps the load on Open Library and the stale-response guard simple. A search can take up to about 43 seconds. |
| A shelf motif on the landing page | The owner kept the landing quiet so the empty space keeps the focus on the search. The bookshelf shows for no results and in the progress stage. |
| A legend for the badges | The owner left the badges explained only by each card's reason sentence. |
| A "Not it?" hint under the results, and closing the gap in the featured card | Reviewed in the critique runs and left as is. |
| `AllowedHosts: *` replaced by a host list | A list would break the container on any hostname not in it, and the deployment hostnames are not known. Set `AllowedHosts` when you deploy. |
| Removing `style-src-attr 'unsafe-inline'` and `https://*.archive.org` from the Content-Security-Policy | The progress scenes use inline style attributes and cover redirects go through archive.org. Removing either breaks the UI. |
| Requiring https for the OpenAI-compatible base URL | A LAN or local gateway over http is a supported setup. Readiness reports `degraded` when an API key would go over http to a non-loopback host. |
| Polly through `AddResilienceHandler` (`Microsoft.Extensions.Http.Resilience`) on the HttpClients | The request gate and the 429 cooldown live in the catalog, and the unit tests build the clients directly. Pipelines from `Polly.Core` run inside the catalog and the AI clients instead, so the gate, the cooldown and the tests stay as they were. Revisit if resilience should apply to every HttpClient, for example the probes. |
| A named Cloudflare Tunnel with a stable hostname | Needs a domain in the Cloudflare account, and the account has none. A tunnel was created, configured and deleted on 2026-10-14. `quick-tunnel` in `docker-compose.yml` gives a temporary `trycloudflare.com` URL instead. Revisit when a domain is added: create the tunnel with `cf tunnels create`, add its hostname to the ingress, and run `cloudflared` with the tunnel token from `.env`. |
| A Latin-script author name on the byline | Needs alias handling in the API and changes the "names as stored" rule. Listed in the README under known limitations. |

## Changed after the first draft

| Draft | Built | Why |
|---|---|---|
| Author-only queries use `/authors/{id}/works.json` | `/search.json?sort=editions` | The works endpoint has no popularity order. |
| Gemini only | Provider-neutral AI seam plus an OpenAI-compatible client | Gemini's free tier was unreliable when tested (see the README). |
| One parsed hypothesis | A list of hypotheses | The heuristic parser needs several guesses when no AI is available. |
| 8 detail lookups per search | 6, plus an author cap, a request limit and a 429 cooldown | Open Library rate-limits heavy use. |
| Retry button on the error banner (earlier tried and dropped, reason not recorded) | A "Try again" button that repeats the last search, enabled immediately (now on the error toast) | Accessibility and recovery pass on the UI. It does not wait for a 429 cooldown, so during one it fails fast with the same error. |
| Full-width banners for the error, the AI notice and the weak-match message, and inline text for the empty state | Dismissable toasts in a fixed stack (bottom right, across the bottom on phones) | A toast does not move the layout and keeps Try again next to the message. The first version sat at the top on phones and covered the header and search box, so it moved to the bottom. |
| Titles and names shown as Open Library stores them | The matched edition title is the headline and the stored title sits beneath it ("Catalogued as"). Author names are still shown as stored | A reader who typed an English title saw a Japanese or Swedish one as the answer (`matchedTitle` in the API). |
| The "Basic search mode" toast returns after every search | It shows only next to results and stays dismissed for the page session | It repeated on every search and stacked on the empty-state toast. |
| Neutral blue-grey page, system sans for everything | Warm paper, a serif for the page question and book titles, a ledge under every cover (`DESIGN.md`) | The product's character showed only in the empty and progress states. |
| 260px of page padding while any toast shows | 150px for one toast, 260px for two | A single toast left a large blank area. |
| Static files and API responses served uncompressed | gzip through the ASP.NET response compression middleware (the script goes from about 234 KB to 85 KB) | The seventh critique measured it. HTTPS compression stays off, which is the framework default, and a proxy in front can compress instead. |
| The wordmark is plain text | The wordmark is a link to `/` that reloads the page with no query and an empty search box | A reader needs a way back to a clean start. A plain link does exactly that with no state handling. |
| Progress stage steps advance every 2.5 seconds | Each step has its own time: understand 10 s, search 2 s, match 1 s, explain 30 s (`STEP_MS` in `web/src/lib/progress.ts`) | A logged search took 11.7 s for the AI parse, 1.6 s for Open Library and 29.5 s for the AI explanations, so equal steps showed "Writing explanations" for too short a time. The times are estimates, because the API reports no progress |
| Temperature fixed at 0 in both AI clients, nothing else sent | `Ai:Temperature`, `Ai:TopK`, `Ai:TopP`, `Ai:Seed` and `Ai:ReasoningEffort` from configuration, one shared setting for both providers. Defaults keep today's request (temperature 0, nothing else) | The values should be tunable per deployment without a code change. Everything except the temperature is sent only when set, because some OpenAI-compatible gateways reject `top_k`, `seed` or `reasoning_effort` (a third-party report said xAI Grok models reject `reasoning_effort`, but `api.x.ai` accepted it for `grok-4.7` on 2026-10-14). An out-of-range temperature, top-k or top-p, or a reasoning effort that is not a short word, is not sent and readiness reports it |
| A fixed list of reasoning effort values | Any short lowercase word, passed through (`reasoning_effort` for OpenAI-compatible, `thinkingConfig.thinkingLevel` for Gemini) | The accepted words differ by model (`minimal`, `low`, `medium`, `high`, and on some `none` or `xhigh`), so a fixed list would block valid values. Gemini's older `thinkingBudget` is not offered |
| `/api/health/config` answers any caller on the same machine | Off (404 for everyone) unless `Api:Health:ExposeConfig` is true, and still local-only when on | A reverse proxy on the same machine that adds no forwarding header makes every outside caller look local. nginx adds none by default |
| `/api/health/ready` returns the full per-dependency report to everyone | Only `{ "status": ... }` to ordinary callers, with the status codes unchanged. The full report goes to a local caller when `Api:Health:ExposeConfig` is true | The breakdown named the AI provider and said whether its key was missing or rejected |
| The search limit matched the exact path `/api/search` | Trailing slashes are ignored when matching | Routing accepts `/api/search/`, which reached the controller with no limit (found by a live check, 13 of 13 requests passed) |
| Security headers set before the exception handler | Set in `OnStarting` | The exception handler clears response headers, so 500, 502 and 413 responses had none |
| Shared Open Library request runs on the first caller's cancellation token | Runs on its own lifetime. Each caller waits with its own token, and the in-flight entry is removed when the request ends | One reader disconnecting failed another reader's search with a 500 |
| No cap on outgoing response size | 2 MB per response, also in the HTTP logging buffer | A faulty or hostile upstream could fill memory |
| Open Library retry written by hand in `FetchAsync` (loop and `Task.Delay`), no retry or circuit for the AI | `OpenLibraryResiliencePipeline` and `AiResiliencePipeline` (Polly): retry, circuit breaker and timeouts, with circuit counters through `FindThatBookTelemetry` and settings in `OpenLibrary:Resilience:*` and `Ai:Resilience:*` | A dead AI provider cost every search up to 60 s again, and the AI had no retry for a passing 503. The AI retries only 5xx and network errors (not timeouts or 429) and counts 429 towards its circuit. Open Library does not count a 429, the cooldown owns it. Tuning values (ratio 0.5, minimum 6 and 4 calls, break 20 s and 30 s) are first guesses, not measured |
| `Gemini` and `OpenAiCompatible` configuration sections at the top level (`Gemini__ApiKey`, `OpenAiCompatible__BaseUrl` and so on) | `Ai:Gemini` and `Ai:OpenAiCompatible` (`Ai__Gemini__ApiKey`, `Ai__OpenAiCompatible__BaseUrl` and so on). The `.env` variable names (`AI_GEMINI_API_KEY`, `AI_OPEN_AI_COMPATIBLE_BASE_URL` and so on) are unchanged | Every AI setting now sits under one `Ai` section. This breaks anything that set the old keys directly: an env var `Gemini__ApiKey`, a user secret `Gemini:ApiKey`, `OpenAiCompatible__*`. They are ignored silently, and the readiness check then reports the Gemini key as not set (degraded) |
| `Telemetry`, `Health` and `RateLimit` configuration sections at the top level (`Telemetry__Enabled`, `Health__ExposeConfig`, `RateLimit__*`) | `Api:Telemetry`, `Api:Health` and `Api:RateLimit` (`Api__Telemetry__Enabled`, `Api__Health__ExposeConfig`, `Api__RateLimit__*`). The `.env` variable names (`API_TELEMETRY_ENABLED`, `API_HEALTH_EXPOSE_CONFIG`, `API_RATE_LIMIT_*` and so on) and the standard `OTEL_*` variables are unchanged | The settings of the API host now sit under one `Api` section, next to `Ai` and `OpenLibrary`. This breaks anything that set the old keys directly. They are ignored silently, so `Health__ExposeConfig=true` no longer opens `/api/health/config`, `Telemetry__Enabled=true` no longer turns telemetry on, and the rate limits fall back to their defaults (10 per minute, 8 at once) |
| A `Model` setting in each of `Ai:Gemini` and `Ai:OpenAiCompatible`, with the `.env` variables `GEMINI_MODEL` and `OPENAI_MODEL` | One `Ai:Model` (`Ai__Model`, `AI_MODEL`) for the selected provider. Blank uses that provider's default. `GET /api/health/config` shows it as `ai.model` | Only one provider runs at a time, so two model settings meant one was always unused. The model has to change together with `Ai:Provider`, because a model id of one provider is wrong for the other. This breaks anything that set the old keys: they are ignored silently and the provider default is used instead |
| `.env` variable names chosen one by one (`GEMINI_API_KEY`, `OPENAI_BASE_URL`, `OPENLIBRARY_CONTACT`, `OPENLIBRARY_CIRCUIT_*`, `RATE_LIMIT_SEARCHES_PER_MINUTE`, `HEALTH_EXPOSE_CONFIG`, `TELEMETRY_ENABLED` and so on) | One rule: the variable is the configuration key in upper snake case with camelCase words split (`Ai:Gemini:ApiKey` is `AI_GEMINI_API_KEY`, `Ai:OpenAiCompatible:BaseUrl` is `AI_OPEN_AI_COMPATIBLE_BASE_URL`, `OpenLibrary:Resilience:CircuitBreakerBreakSeconds` is `OPEN_LIBRARY_RESILIENCE_CIRCUIT_BREAKER_BREAK_SECONDS`, `Api:RateLimit:SearchPermitsPerMinute` is `API_RATE_LIMIT_SEARCH_PERMITS_PER_MINUTE`). `AI_*` names that already followed it (`AI_PROVIDER`, `AI_MODEL`, `AI_TEMPERATURE`, `AI_RESILIENCE_*`) and the standard `OTEL_*` variables did not change. A test derives the name from every `Section__Key` line of `docker-compose.yml` and fails on a mismatch | The `.env` names no longer matched the new configuration structure, so a reader could not tell which setting a variable sets. The long names are the cost of the rule. This breaks every `.env` that uses an old name: the old variables are ignored silently and the defaults apply, and `.env` is git-ignored so each person must rename theirs |
